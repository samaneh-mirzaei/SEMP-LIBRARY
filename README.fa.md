# 📚 سیستم مدیریت کتابخانه (Library API)

یک API ساده برای مدیریت کتاب‌های یک کتابخانه، ساخته‌شده با **FastAPI** و **PostgreSQL**. این پروژه به‌عنوان تمرین دوره‌ی بک‌اند (بوتکمپ) نوشته شده است. داده‌ها در یک دیتابیس **PostgreSQL** ذخیره می‌شوند، بنابراین با خاموش و روشن شدن سرور از بین نمی‌روند.

## امکانات

- ثبت، مشاهده‌ی لیست، دریافت، ویرایش جزئی و حذف کتاب
- ذخیره‌سازی دائمی داده‌ها در PostgreSQL
- شناسه‌ی یکتا (UUID) برای هر کتاب، به‌جای ایندکس لیست
- اعتبارسنجی خودکار ورودی و خروجی با Pydantic
- مستندات تعاملی خودکار (Swagger UI و ReDoc)
- ساخت خودکار جدول‌ها هنگام اجرای سرور
- بارگذاری اختیاری داده‌های نمونه هنگام اجرای سرور
- تنظیمات قابل تغییر از طریق متغیرهای محیطی یا فایل `.env`
- مجموعه تست خودکار با pytest (روی دیتابیس موقت، بدون دست زدن به داده‌های اصلی)

## نصب و راه‌اندازی

### ۱. دریافت پروژه

```bash
git clone https://github.com/tiredpotatoe/SEMP-LIBRARY.git
cd SEMP-LIBRARY
```

### ۲. نصب وابستگی‌ها

از **پوشه‌ی اصلی پروژه** (کنار فایل `pyproject.toml`) اجرا کنید:

```bash
uv sync
```

این یک دستور همه‌کاره است:

- در صورت نیاز نسخه‌ی مناسب پایتون را دریافت می‌کند
- محیط مجازی `.venv` را خودکار می‌سازد (**نیازی به ساخت یا فعال‌سازی دستی آن نیست**)
- وابستگی‌های اجرا و توسعه (مثل pytest و httpx) را با نسخه‌های ثبت‌شده در `uv.lock` نصب می‌کند
- خود پروژه (`library`) را در حالت editable نصب می‌کند، پس پایتون پکیج `library` را از هر جا پیدا می‌کند

برای نصب فقط وابستگی‌های **اجرای برنامه** (بدون ابزارهای توسعه و تست):

```bash
uv sync --no-dev
```

### ۳. راه‌اندازی دیتابیس

پیش از اجرای برنامه، PostgreSQL باید نصب و روشن باشد و یک دیتابیس به نام `library` وجود داشته باشد. مراحل در بخش بعد آمده است.

### ۴. ساخت فایل `.env`

اطلاعات اتصال به دیتابیس را در فایل `.env` بگذارید (بخش «تنظیمات» را ببینید).

### افزودن پکیج جدید

```bash
uv add <package>          # وابستگی اجرا
uv add --dev <package>    # وابستگی توسعه (مثل ruff)
```

این دستورها `pyproject.toml` و `uv.lock` را خودکار به‌روز می‌کنند.

## راه‌اندازی دیتابیس

### نصب PostgreSQL

#### 🪟 ویندوز

1. نصب‌کننده را از https://www.postgresql.org/download/windows/ دریافت و اجرا کنید.
2. همه‌ی مراحل را با تنظیمات پیش‌فرض بگذرانید (پورت `5432`).
3. در مرحله‌ی تعیین رمز، برای کاربر `postgres` یک رمز انتخاب کنید و **آن را یادداشت کنید**.
4. PostgreSQL به‌صورت یک سرویس ویندوز نصب می‌شود و همیشه در پس‌زمینه اجرا می‌ماند.

#### 🐧 لینوکس (اوبونتو)

```bash
sudo apt install postgresql
sudo systemctl start postgresql
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'postgres123';"
```

#### 🍎 مک

```bash
brew install postgresql@17
brew services start postgresql@17
```

#### 🐳 با Docker (روی همه‌ی سیستم‌ها)

```bash
docker run --name library-db -e POSTGRES_PASSWORD=postgres123 -e POSTGRES_DB=library -p 5432:5432 -d postgres:17
```

با این روش دیتابیس `library` از قبل ساخته می‌شود و نیازی به مرحله‌ی بعد نیست.

### ساخت دیتابیس `library`

**با pgAdmin (ویندوز):** برنامه را باز کنید، روی **Databases** راست‌کلیک کنید و **Create ← Database...** را بزنید. نام را `library` بگذارید و **Save** کنید.

**یا با خط فرمان:**

```bash
psql -U postgres -h localhost -c "CREATE DATABASE library;"
```

> فقط خود دیتابیس را بسازید. جدول `books` را برنامه هنگام اجرا خودش می‌سازد.

## اجرای برنامه

دستور زیر را از **پوشه‌ی اصلی پروژه** اجرا کنید:

```bash
uv run uvicorn library.main:app --reload
```

- `uv run` دستور را داخل محیط مجازی پروژه اجرا می‌کند (نیازی به فعال‌سازی `.venv` نیست)
- `library.main:app` یعنی شیء `app` داخل فایل `main.py` از پکیج `library`
- `--reload` سرور را با هر تغییر کد دوباره راه‌اندازی می‌کند (فقط برای توسعه)

هنگام شروع، برنامه جدول `books` را (در صورت نبودن) می‌سازد و سپس در صورت فعال بودن `SEED_DATA` داده‌های نمونه را بارگذاری می‌کند.

پس از اجرا، آدرس‌های زیر در دسترس هستند:

| آدرس | توضیح |
|---|---|
| http://127.0.0.1:8000 | صفحه‌ی اصلی API |
| http://127.0.0.1:8000/docs | مستندات تعاملی (Swagger UI) |
| http://127.0.0.1:8000/redoc | مستندات ReDoc |

> ساده‌ترین راه برای امتحان کردن همه‌ی endpointها، صفحه‌ی `/docs` است. هر endpoint را باز کنید، دکمه‌ی **Try it out** را بزنید و درخواست بفرستید، بدون نیاز به نوشتن هیچ دستوری.

## مرجع API

| متد | مسیر | توضیح | کد موفقیت |
|---|---|---|---|
| `GET` | `/books` | دریافت لیست کتاب‌ها | `200` |
| `POST` | `/books` | افزودن کتاب جدید | `201` |
| `GET` | `/books/{book_id}` | دریافت اطلاعات یک کتاب | `200` |
| `PATCH` | `/books/{book_id}` | ویرایش اطلاعات یک کتاب | `200` |
| `DELETE` | `/books/{book_id}` | حذف یک کتاب | `204` |

### مدل کتاب

| فیلد | نوع | الزامی | پیش‌فرض | توضیح |
|---|---|---|---|---|
| `id` | UUID | فقط در پاسخ | تولید توسط سرور | شناسه‌ی یکتای کتاب |
| `title` | رشته | بله | - | عنوان کتاب |
| `author` | رشته | بله | - | نویسنده |
| `is_available` | بولی | خیر | `true` | آیا کتاب موجود است؟ |
| `published_date` | رشته | خیر | `null` | تاریخ انتشار (مثلاً `1965-08-01`) |

نکته‌ها:

- هنگام ساخت کتاب نباید `id` بفرستید، سرور خودش آن را می‌سازد (اگر هم بفرستید نادیده گرفته می‌شود).
- در `PATCH` فقط فیلدهایی را بفرستید که می‌خواهید تغییر کنند. بقیه‌ی فیلدها دست‌نخورده می‌مانند.

### کدهای خطا

| کد | معنی |
|---|---|
| `404 Not Found` | کتابی با این شناسه وجود ندارد |
| `422 Unprocessable Entity` | ورودی نامعتبر است (فیلد الزامی ارسال نشده، نوع داده اشتباه است، یا شناسه فرمت UUID ندارد) |
| `500 Internal Server Error` | معمولاً مشکل اتصال به دیتابیس است. لاگ سرور را ببینید |

## نمونه‌های استفاده

در مثال‌های زیر فرض شده سرور روی `http://127.0.0.1:8000` در حال اجراست. به‌جای `<BOOK_ID>` شناسه‌ی یک کتاب را قرار دهید.

> 🪟 **کاربران ویندوز:** در PowerShell دستور `curl` در واقع یک نام مستعار برای `Invoke-WebRequest` است و مثال‌های `curl` پایین کار نمی‌کنند. از `curl.exe` یا از نسخه‌ی `Invoke-RestMethod` که کنار هر مثال آمده استفاده کنید.

### افزودن کتاب (POST)

**لینوکس / مک / `curl.exe` در ویندوز:**

```bash
curl -X POST http://127.0.0.1:8000/books \
  -H "Content-Type: application/json" \
  -d '{"title": "Dune", "author": "Frank Herbert", "published_date": "1965-08-01"}'
```

**PowerShell:**

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/books `
  -ContentType "application/json" `
  -Body '{"title": "Dune", "author": "Frank Herbert", "published_date": "1965-08-01"}'
```

پاسخ (`201 Created`):

```json
{
  "title": "Dune",
  "author": "Frank Herbert",
  "is_available": true,
  "published_date": "1965-08-01",
  "id": "3f2b8c1e-5d4a-4b7e-9c1a-2e8f6a7b9d01"
}
```

### دریافت لیست کتاب‌ها (GET)

```bash
curl http://127.0.0.1:8000/books
```

```powershell
Invoke-RestMethod http://127.0.0.1:8000/books
```

### دریافت یک کتاب (GET)

```bash
curl http://127.0.0.1:8000/books/<BOOK_ID>
```

```powershell
Invoke-RestMethod http://127.0.0.1:8000/books/<BOOK_ID>
```

### ویرایش کتاب (PATCH)

برای مثال، علامت‌گذاری کتاب به‌عنوان «قرض داده شده»:

```bash
curl -X PATCH http://127.0.0.1:8000/books/<BOOK_ID> \
  -H "Content-Type: application/json" \
  -d '{"is_available": false}'
```

```powershell
Invoke-RestMethod -Method Patch -Uri http://127.0.0.1:8000/books/<BOOK_ID> `
  -ContentType "application/json" `
  -Body '{"is_available": false}'
```

### حذف کتاب (DELETE)

```bash
curl -X DELETE http://127.0.0.1:8000/books/<BOOK_ID>
```

```powershell
Invoke-RestMethod -Method Delete -Uri http://127.0.0.1:8000/books/<BOOK_ID>
```

پاسخ موفق `204 No Content` است و بدنه‌ای ندارد.

## تنظیمات

تنظیمات برنامه در فایل `src/library/config.py` تعریف شده‌اند. هر تنظیم یک مقدار پیش‌فرض دارد، اما **آدرس دیتابیس را باید متناسب با سیستم خودتان در `.env` بگذارید** (رمز واقعی را هرگز در `config.py` ننویسید).

| تنظیم | متغیر محیطی | نوع | پیش‌فرض | توضیح |
|---|---|---|---|---|
| `app_name` | `APP_NAME` | رشته | `Library API` | نام برنامه (در `/docs` نمایش داده می‌شود) |
| `debug` | `DEBUG` | بولی | `false` | حالت دیباگ |
| `seed_data` | `SEED_DATA` | بولی | `true` | بارگذاری داده‌های نمونه هنگام اجرا |
| `database_url` | `DATABASE_URL` | رشته | `postgresql+psycopg://postgres:postgres@localhost:5432/library` | آدرس اتصال به PostgreSQL |

مقدارهای بولی را می‌توانید با `true` / `false` (یا `1` / `0`) بنویسید. نام متغیرهای محیطی به بزرگی و کوچکی حروف حساس نیست.

### ساختار آدرس دیتابیس

```
postgresql+psycopg://کاربر:رمز@میزبان:پورت/نام_دیتابیس
```

| بخش | معنی |
|---|---|
| `postgresql+psycopg` | نوع دیتابیس و درایور پایتون |
| کاربر | نام کاربری (معمولاً `postgres`) |
| رمز | رمزی که هنگام نصب PostgreSQL تعیین کردید |
| میزبان | `localhost` یعنی دیتابیس روی همین سیستم است |
| پورت | پیش‌فرض `5432` |
| نام_دیتابیس | `library` |

> اگر رمز شما نویسه‌های خاص مثل `@` یا `#` یا `/` دارد، آدرس خراب می‌شود. برای شروع از رمز ساده (حروف و عدد) استفاده کنید.

### روش اول: فایل `.env`

یک فایل به نام `.env` در **پوشه‌ی اصلی پروژه** (همان جایی که دستور `uv run` را اجرا می‌کنید) بسازید:

```
APP_NAME=Library API (dev)
DEBUG=true
SEED_DATA=true
DATABASE_URL=postgresql+psycopg://postgres:رمز_شما@localhost:5432/library
```

> فایل `.env` مخصوص هر سیستم است و در `.gitignore` قرار دارد. آن را در گیت‌هاب commit نکنید، چون رمز دیتابیس در آن است. مطمئن شوید نام فایل دقیقاً `.env` است و `.env.txt` نیست.

برای بررسی اینکه برنامه مقدار را درست می‌خواند:

```bash
uv run python -c "from library.config import settings; print(settings.database_url)"
```

### روش دوم: متغیر محیطی موقت

**ویندوز (PowerShell):**

```powershell
$env:SEED_DATA = "false"
uv run uvicorn library.main:app --reload
```

**ویندوز (CMD):**

```bat
set SEED_DATA=false
uv run uvicorn library.main:app --reload
```

**لینوکس / مک:**

```bash
SEED_DATA=false uv run uvicorn library.main:app --reload
```

اگر یک تنظیم در چند جا مقدار داشته باشد، اولویت به این ترتیب است:

1. متغیر محیطی واقعی سیستم (بالاترین اولویت)
2. فایل `.env`

## داده‌های نمونه (Seed)

هنگام اجرای سرور، اگر `SEED_DATA` برابر `true` باشد (پیش‌فرض) و جدول `books` **خالی** باشد، **۵ کتاب نمونه** بارگذاری می‌شود. کد این بخش در `src/library/data/seed.py` است و با مکانیزم **lifespan** در FastAPI اجرا می‌شود.

چون داده‌ها حالا در دیتابیس ذخیره می‌شوند:

- نمونه‌ها فقط **یک‌بار** (وقتی جدول خالی است) اضافه می‌شوند و در اجراهای بعدی تکرار نمی‌شوند.
- کتاب‌هایی که خودتان اضافه، ویرایش یا حذف می‌کنید بعد از راه‌اندازی مجدد باقی می‌مانند.
- اگر همه‌ی کتاب‌ها را حذف کنید و سرور را دوباره اجرا کنید، نمونه‌ها دوباره بارگذاری می‌شوند.

**فعال کردن:** `SEED_DATA=true` (یا اصلاً چیزی تنظیم نکنید)

**غیرفعال کردن:** `SEED_DATA=false` (روش‌های تنظیم در بخش قبل توضیح داده شد). در این حالت اگر دیتابیس خالی باشد `GET /books` یک لیست خالی `[]` برمی‌گرداند.

شناسه‌ی کتاب‌های نمونه **ثابت** است، پس آدرس‌های زیر همیشه کار می‌کنند:

| عنوان | شناسه |
|---|---|
| Dune | `11111111-1111-4111-8111-111111111111` |
| 1984 | `22222222-2222-4222-8222-222222222222` |
| Pride and Prejudice | `33333333-3333-4333-8333-333333333333` |

## اجرای تست‌ها

ابتدا مطمئن شوید وابستگی‌های توسعه نصب شده‌اند (دستور `uv sync` به‌طور پیش‌فرض آن‌ها را هم نصب می‌کند):

```bash
uv sync
```

سپس از **پوشه‌ی اصلی پروژه** (کنار فایل `pyproject.toml`) اجرا کنید:

```bash
uv run pytest
```

برای خروجی مفصل‌تر:

```bash
uv run pytest -v
```

اجرای یک تست مشخص:

```bash
uv run pytest tests/test_books.py::test_create_book
```

چند نکته درباره‌ی تست‌ها:

- تست‌ها **به PostgreSQL وصل نمی‌شوند** و روی یک دیتابیس SQLite درون‌حافظه کار می‌کنند، پس داده‌های اصلی شما هرگز تغییر نمی‌کنند و نیازی به روشن بودن PostgreSQL نیست.
- فیکسچر `clean_store` در `tests/conftest.py` برای هر تست یک دیتابیس خالی می‌سازد و وابستگی `get_db` را با آن جایگزین می‌کند، پس تست‌ها مستقل از هم هستند.
- `TestClient` بدون `with` استفاده می‌شود، بنابراین lifespan اجرا نمی‌شود و داده‌های نمونه بارگذاری **نمی‌شوند**.
- تست‌ها فقط از طریق HTTP با API کار می‌کنند و از نحوه‌ی ذخیره‌سازی داده‌ها خبر ندارند.

## معماری پروژه

کد به چند لایه تقسیم شده و هر لایه فقط یک کار دارد. هر لایه فقط با لایه‌ی پایین‌تر از خودش صحبت می‌کند:

```
درخواست HTTP
     │
     ▼
 Router   (routers/)   ← دریافت درخواست، گرفتن session دیتابیس (Depends(get_db))
     │
     ▼
 Service  (services/)  ← منطق برنامه، مثلاً «کتاب پیدا نشد» یک خطاست
     │
     ▼
 Data     (data/)      ← خواندن و نوشتن در PostgreSQL
     │
     ▼
 PostgreSQL
```

| لایه | مسئولیت |
|---|---|
| `schemas/` | شکل داده‌ها در API: `BookCreate` (ورودی ساخت)، `BookUpdate` (ورودی ویرایش)، `BookRead` (خروجی) |
| `routers/` | تعریف مسیرها با `APIRouter` و تزریق session دیتابیس |
| `services/` | منطق برنامه (ساخت شناسه، اعمال ویرایش، بررسی وجود کتاب) |
| `data/database.py` | ساخت `engine` و `SessionLocal` و تابع `get_db` |
| `data/models.py` | تعریف جدول `books` با SQLAlchemy |
| `data/book_store.py` | تنها جایی که کوئری‌های دیتابیس نوشته می‌شود؛ ورودی و خروجی آن مدل‌های `BookRead` است |
| `exceptions.py` | خطای `BookNotFoundError` که در `main.py` به پاسخ `404` تبدیل می‌شود |

چند نکته درباره‌ی طراحی:

- **دو نوع «مدل کتاب» داریم:** `BookRead` و بقیه‌ی schemaها برای شکل داده‌ها در API هستند (Pydantic)، و `Book` در `models.py` نماینده‌ی جدول دیتابیس است (SQLAlchemy). تبدیل این دو به هم فقط در `book_store.py` انجام می‌شود، پس سرویس‌ها و روترها از وجود SQLAlchemy خبر ندارند.
- **session در هر درخواست:** تابع `get_db` برای هر درخواست یک session باز می‌کند و پس از پایان آن می‌بندد.
- **`pool_pre_ping=True`** در ساخت engine فعال است تا اگر PostgreSQL ری‌استارت شود، اتصال‌های مرده به‌جای خطا دوباره ساخته شوند.
- جدول‌ها هنگام شروع برنامه با `Base.metadata.create_all` ساخته می‌شوند.

## محدودیت‌ها

این پروژه یک تمرین آموزشی است و برای استفاده‌ی واقعی (Production) طراحی نشده است:

- **مهاجرت (Migration) ندارد.** `create_all` فقط جدول‌های ناموجود را می‌سازد و ستون‌های جدول موجود را تغییر نمی‌دهد. اگر مدل را عوض کنید باید جدول را دستی تغییر دهید یا از ابزاری مثل Alembic استفاده کنید.
- **احراز هویت و سطح دسترسی ندارد.** هر کسی می‌تواند کتاب‌ها را تغییر دهد.
- `published_date` فعلاً یک رشته‌ی ساده است و فرمت تاریخ را بررسی نمی‌کند.
- امکان جستجو، فیلتر و صفحه‌بندی (Pagination) وجود ندارد.
- تنظیمات اتصال (اندازه‌ی pool و غیره) روی مقادیر پیش‌فرض است.

ایده‌هایی برای توسعه‌ی بعدی: افزودن Alembic برای مهاجرت‌ها، استفاده از نوع `date` برای `published_date`، افزودن جستجو و صفحه‌بندی، و افزودن مدل اعضا و امانت کتاب.

## عیب‌یابی

| مشکل | علت و راه‌حل |
|---|---|
| `uv is not recognized` / `command not found: uv` | uv نصب نشده یا ترمینال بعد از نصب دوباره باز نشده است. بخش «نصب uv» را ببینید |
| `ModuleNotFoundError: No module named 'library'` | هنوز `uv sync` را اجرا نکرده‌اید، یا دستور را بدون `uv run` و خارج از محیط مجازی اجرا کرده‌اید |
| `ModuleNotFoundError: No module named 'library.data.database'` (یا `models`) | فایل وجود ندارد یا نام آن اشتباه است (مثلاً `database,py` به‌جای `database.py`). با `dir src\library\data` نام فایل‌ها را بررسی کنید |
| `No module named 'psycopg'` | درایور نصب نشده است. `uv sync` را اجرا کنید |
| `uvicorn is not recognized` / `command not found` | دستور را با `uv run` شروع کنید (`uv run uvicorn ...`) و اگر باز هم خطا داد یک‌بار `uv sync` بزنید |
| `Address already in use` | پورت ۸۰۰۰ اشغال است. از پورت دیگر استفاده کنید: `--port 8001` |
| `'Settings' object has no attribute 'database_url'` | فیلد `database_url` به کلاس `Settings` در `config.py` اضافه نشده است |
| `password authentication failed for user "postgres"` | رمز داخل `DATABASE_URL` با رمز PostgreSQL یکی نیست. رمز را در `.env` اصلاح کنید |
| آدرس دیتابیس همچنان مقدار پیش‌فرض را نشان می‌دهد | فایل `.env` پیدا یا خوانده نمی‌شود. نام آن باید دقیقاً `.env` باشد (نه `.env.txt`) و کنار `pyproject.toml` باشد. سرور را دوباره راه‌اندازی کنید |
| `connection refused` / `could not connect to server` | PostgreSQL روشن نیست یا پورت اشتباه است. در ویندوز از `services.msc` سرویس `postgresql-x64-...` را Start کنید |
| `database "library" does not exist` | دیتابیس را نساخته‌اید. بخش «ساخت دیتابیس library» را ببینید |
| `server closed the connection unexpectedly` | PostgreSQL ری‌استارت شده یا اتصال قطع شده است. سرور FastAPI را دوباره اجرا کنید و مطمئن شوید `pool_pre_ping=True` در `database.py` هست |
| `GET /books` لیست خالی برمی‌گرداند | `SEED_DATA=false` تنظیم شده، یا همه‌ی کتاب‌ها را حذف کرده‌اید و هنوز سرور را ری‌استارت نکرده‌اید |
| تغییر `.env` اعمال نمی‌شود | سرور را کامل متوقف (`Ctrl+C`) و دوباره اجرا کنید و مطمئن شوید `.env` در پوشه‌ی اجرای دستور است |
| `422 Unprocessable Entity` | ورودی نامعتبر است. پاسخ سرور دقیقاً می‌گوید کدام فیلد مشکل دارد |
| خطای `httpx` یا `pytest` هنگام اجرای تست‌ها | وابستگی‌های توسعه نصب نشده‌اند. `uv sync` را بدون `--no-dev` اجرا کنید |
